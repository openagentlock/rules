OpenAgentLock Rules

Community-maintained policy rules for the OpenAgentLock firewall. Search, copy, install.

Using the upstream registry

The default registry is openagentlock/rules — this site. Once you have OpenAgentLock running locally, you can install any rule you find here: 

# list everything available in the upstream registry
agentlock rules search

# install a specific rule by id
agentlock rules install rogue.destructive-bash

# sync periodically to pick up new + updated rules
agentlock rules sync

The CLI verifies the rule against rule.schema.json before merging it into your local policy. Verdicts run through the same gate evaluator as built-in rules — there is no separate code path.

Run your own registry

Any git repo with the same layout works. Use this for company-internal rules you do not want to upstream:

  1. Fork or copy this repo's structure: rules/<id>/, schema/, tools/, site/.
  2. Drop your rule directories in rules/ and update site/data/index.json via bun run build-index.
  3. Push to any git host — GitHub, GitLab, self-hosted Gitea, whatever. The CLI just clones a URL.
  4. On the OpenAgentLock host, register it as an additional registry: 
# register an extra registry on top of the upstream default
agentlock rules add https://github.com/your-org/your-rules.git

# rules are merged at sync time; ids must be unique within a registry
agentlock rules sync

# list registries that the daemon currently pulls from
agentlock rules sources

Multiple registries are supported. The upstream openagentlock/rules is included by default but can be removed with agentlock rules remove openagentlock/rules if your environment has policy reasons to bind only to a private source.

Contribute a rule

Open a PR against openagentlock/rules:

  1. Fork the repo.
  2. Copy rules/destructive-bash/ as a template; keep one rule per directory.
  3. Run bun run validate and bun run build-index locally before pushing.
  4. Open the PR; CI will re-run both.

v1 ships unsigned. Per-rule author signatures and end-to-end install verification are tracked in the GitHub repo issues.
